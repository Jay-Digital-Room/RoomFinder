# RoomFinder — 부동산 매물 통합검색

직방·다방·네이버부동산 등 여러 플랫폼에 흩어진 매물을 **한 화면에서 검색**하고,
**같은 매물이 여러 곳에 올라온 경우 하나로 묶어 플랫폼별 가격을 비교**해 주는 서비스입니다.

> ⚠️ 현재는 **MVP(데모)** 단계로, 각 플랫폼 데이터는 실제 데이터가 아닌 **가상의 목업 데이터**입니다.
> 실제 데이터를 붙이기 전에 아래 [데이터 수집과 법적 이슈](#데이터-수집과-법적-이슈)를 꼭 읽어주세요.

## 주요 기능

- **통합 검색**: 여러 플랫폼의 매물을 공통 형식으로 정규화해서 한 목록·지도에 표시
- **중복 매물 자동 통합**: 주소·전용면적·층·거래유형이 같으면 같은 매물로 판단해 하나로 묶음
  - 플랫폼마다 다른 표기를 흡수: `서울특별시`/`서울시`/생략, `123-4번지`, 평↔㎡, `3층`/`3/15`/`B1`/`반지하`/`고/25`, `2억 1,000`/`1억5000` 등
- **플랫폼별 가격 비교**: 같은 매물인데 어디가 더 싸게 올라왔는지, 최저가와 차액 표시
- **필터**: 거래유형(매매/전세/월세), 방 종류, 플랫폼, 보증금·월세·면적 범위, "2곳 이상 등록", "가격 차이 있음", 지도 영역
- **지도**: 가격 핀 + 줌아웃 시 클러스터링 (Leaflet + OpenStreetMap)
- **모바일 대응 / 앱처럼 설치 가능(PWA)**: 휴대폰에서 "홈 화면에 추가"하면 앱처럼 실행
- **장애 격리**: 일부 플랫폼이 느리거나 실패해도 나머지 결과로 응답 (소스별 타임아웃)
- 필터 상태가 URL에 저장되어 **검색 결과 공유** 가능

## 실행 방법

Node.js 20 이상만 있으면 됩니다. (외부 패키지 의존성 없음)

```bash
npm start          # http://localhost:3000
npm run dev        # 파일 변경 시 자동 재시작
npm test           # 테스트
```

환경 변수:

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `3000` | 서버 포트 |
| `SOURCES` | (전체) | 활성화할 소스, 예: `zigbang,naver` |
| `CACHE_TTL_MS` | `300000` | 수집 결과 캐시 시간(ms) |

## 구조

```
server/
  index.js          HTTP 서버 + API + 정적 파일
  aggregator.js     수집(병렬·타임아웃) → 정규화 → 중복 통합 → 캐시
  query.js          필터·정렬·페이지네이션
  model.js          공통 매물 스키마, 주소/층/금액 파서
  sources/
    index.js        소스 어댑터 레지스트리
    zigbang.js      직방 어댑터 (목업)
    dabang.js       다방 어댑터 (목업)
    naver.js        네이버부동산 어댑터 (목업)
    seed.js         목업 데이터 생성기
public/             프론트엔드 (HTML/CSS/JS, 빌드 불필요)
test/               node:test 기반 테스트
```

### 데이터 흐름

```
[직방] [다방] [네이버] ...  ← 소스 어댑터: fetchRaw() 로 원본 수집
   │      │      │
   └─ normalize() ┘        ← 공통 Listing 스키마로 변환
          │
       dedupe()            ← 동(洞) 단위 버킷 → 쌍별 비교 → Union-Find로 그룹화
          │
   [통합 매물 그룹]         ← 대표가(최저가), 플랫폼별 offers, 가격 차이
          │
   /api/listings  →  웹/모바일 화면
```

### 새 플랫폼 추가하기

`server/sources/` 에 아래 형태의 모듈을 만들고 `sources/index.js` 에 등록하면 됩니다.

```js
export default {
  key: 'peterpan',
  name: '피터팬',
  color: '#00a0e9',
  homepage: 'https://www.peterpanz.com',
  async fetchRaw() { /* 제휴 API 호출 등 */ return [...]; },
  normalize(raw) { /* → Listing (server/model.js 참고) */ },
};
```

### API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/meta` | 소스별 상태·건수, 필터 옵션, 통합 통계 |
| GET | `/api/listings` | 통합 매물 목록. 쿼리: `q, dealType, roomType, source, depositMin/Max, rentMin/Max, areaMin/Max, multiSourceOnly, priceGapOnly, bounds(s,w,n,e), sort(recent·priceAsc·priceDesc·areaDesc·sources), page, pageSize, markers` |
| GET | `/api/listings/:id` | 통합 매물 상세 (플랫폼별 가격 포함) |

## 데이터 수집과 법적 이슈

이 서비스의 핵심 난제는 기술이 아니라 **데이터를 어떻게 합법적으로 확보하느냐**입니다.

**직방·다방·네이버부동산의 데이터를 무단으로 크롤링해서 서비스하는 것은 법적 리스크가 큽니다.**

- 각 플랫폼 이용약관은 자동화된 수집과 상업적 재이용을 금지합니다.
- **저작권법상 데이터베이스제작자의 권리** 침해가 문제될 수 있습니다.
  상당한 투자로 만든 DB의 상당 부분을 복제하는 경우가 해당합니다.
- **부정경쟁방지법**에는 2022년 "데이터 부정사용행위"(제2조 제1호 카목)가 신설됐습니다.
- 기술적 차단을 우회하면 정보통신망법 위반이 문제될 수 있습니다.
  서버에 과부하를 주면 업무방해로 다퉈질 수 있습니다.
- 숙박앱 크롤링 사건처럼 형사상 무죄가 나오더라도, 민사상 손해배상 책임은 별개로 다퉈질 수 있습니다.

그래서 이 코드는 **어댑터 구조만 갖추고 실제 크롤러는 포함하지 않았습니다.**
현실적인 데이터 확보 방법은 다음과 같습니다.

1. **플랫폼과 제휴/공식 API 계약**: 가장 확실한 방법이지만 협상력이 필요합니다.
2. **공인중개사 직접 등록**: 중개사가 여러 플랫폼에 올리는 매물을 우리 서비스에도 한 번에 올리게 합니다.
   "한 번 등록 → 여러 플랫폼 전송" 기능을 미끼로 쓸 수 있습니다.
3. **중개사 매물관리 프로그램(ERP) 연동**: 중개사들이 쓰는 매물관리 솔루션과 제휴합니다.
4. **공공데이터 활용**: 아래 데이터로 "시세 대비 비싼지/싼지" 같은 부가 정보를 제공합니다. (합법·무료)
   - 국토교통부 실거래가 공개시스템 (공공데이터포털 API)
   - 건축물대장, 등기 정보
5. **링크 아웃 방식**: 검색 결과만 보여주고, 상세는 원 플랫폼으로 이동시키는 방식입니다. 리스크가 줄지만 0이 되지는 않습니다.

> 이 내용은 일반적인 정보이며 법률 자문이 아닙니다. 실제 서비스 전에는 반드시 변호사 검토를 받으세요.
