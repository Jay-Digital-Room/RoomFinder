# RoomFinder — 부동산 매물 통합검색 (개인용)

직방·다방·네이버부동산·피터팬에 흩어진 매물을 **한 화면에서 검색**합니다.
**같은 매물이 여러 곳에 올라온 경우 하나로 묶어 플랫폼별 가격을 비교**해 줍니다.

## 주요 기능

- **실제 사이트 크롤링**: 직방, 다방, 네이버부동산, 피터팬의 웹 API에서 원하는 조건의 매물만 수집합니다
  - `npm start` 하면 터미널에서 **지역·거래유형·방 종류·가격·플랫폼**을 먼저 묻고, 그 조건으로 수집하면서 브라우저를 엽니다
  - 조건에 해당하는 요청만 보냅니다. 예를 들어 원룸·월세만 고르면 빌라·오피스텔·매매 요청은 아예 보내지 않습니다
  - 사이트별로 수집이 끝나는 대로 화면에 바로 나타납니다
  - 웹 화면 상단 **"수집 조건"**에서 언제든 조건을 바꾸고 다시 수집할 수 있습니다. 지금 보고 있는 지도 영역을 지역으로 추가할 수도 있습니다
  - 지도에서 원하는 곳으로 이동해 **"이 지역 매물 불러오기"**를 누르면 그 영역만 즉시 수집합니다
  - 이후 1시간마다 같은 조건으로 다시 수집합니다
  - 수집 결과는 `data/listings.live.json`에 저장되어 재시작해도 유지됩니다. 3일간 다시 보이지 않은 매물은 자동으로 정리됩니다
- **중복 매물 자동 통합**: 아래 조건이 맞으면 같은 매물로 묶습니다
  - 거래유형·전용면적·층이 같을 것
  - 그리고 다음 중 하나: 지번이 같음 / 좌표가 40m 이내 / 같은 동 + 층 명시 + 가격이 거의 같음 + 300m 이내
  - 실제 플랫폼은 지번을 숨기고 좌표를 일부러 흐리기 때문에 마지막 규칙이 필요합니다
- **플랫폼별 가격 비교**: 어디가 가장 싼지, 최저가와의 차액을 보여주고 원문 링크를 제공합니다
- **지도**: 카카오맵 또는 네이버 지도를 씁니다. API 키가 없으면 OpenStreetMap으로 대체합니다
- **필터**: 거래유형, 방 종류, 플랫폼, 가격·면적 범위, 2곳 이상 등록, 가격 차이 있음, 지도 영역
- **모바일 대응 + 앱처럼 설치(PWA)**: 휴대폰에서 "홈 화면에 추가"하면 됩니다

## 가장 쉬운 실행 방법 (더블클릭)

1. https://nodejs.org 에서 **LTS** 버전을 설치합니다. 처음 한 번만 하면 됩니다
2. 이 저장소를 ZIP으로 받아 압축을 풉니다
3. 폴더 안의 실행 파일을 **더블클릭**합니다
   - Windows: **`RoomFinder 실행 (Windows).bat`**
   - Mac: **`RoomFinder 실행 (Mac).command`**
4. 검은 창에서 조건을 고르면 브라우저가 자동으로 열립니다. 끌 때는 검은 창을 닫으면 됩니다

| 처음 실행할 때 나오는 경고 | 해결 |
|---|---|
| Windows "PC 보호" 파란 창 | **추가 정보 → 실행** |
| Mac "확인되지 않은 개발자" | 파일을 **오른쪽 클릭 → 열기 → 열기** |

**바탕화면에 아이콘 만들기 (Windows):** 실행 파일을 오른쪽 클릭하고 **보내기 → 바탕 화면에 바로 가기 만들기**를 선택하세요.
다음부터는 바탕화면 아이콘만 더블클릭하면 됩니다.

Node.js가 없으면 실행 파일이 설치 페이지를 자동으로 열어 줍니다. 처음 실행할 때는 필요한 패키지를 자동으로 설치하므로 조금 더 걸립니다.

## 명령어로 실행하기

Node.js **22 이상**이 필요합니다. 외부 패키지는 없습니다.

```bash
npm install              # 처음 한 번 (AI 검색용 패키지)
npm start                # 조건을 물어본 뒤 실제 사이트 수집 + 브라우저 자동 열림
npm run mock             # 가상 데이터로 실행 (화면 확인용, 원문 링크 없음)
npm run crawl            # 크롤러 점검 (아래 "수집이 안 될 때" 참고)
npm test
```

`npm start`를 하면 아래처럼 물어봅니다. 번호를 고르거나 Enter를 눌러 기본값을 쓰면 됩니다.
조건은 `data/conditions.json`에 저장되므로, 다음 실행부터는 Enter 한 번이면 지난 조건으로 바로 시작합니다.

```
🏠 RoomFinder — 어떤 매물을 찾으세요?
① 지역 (역 주변 반경 약 1km, 최대 6곳)
 1) 홍대입구역   2) 합정역   3) 망원역  ... 27) 마곡역
번호 선택 (여러 개는 쉼표, Enter = 홍대입구역): 14,15
② 거래 유형   1) 매매  2) 전세  3) 월세
③ 방 종류     1) 원룸  2) 투룸  3) 쓰리룸+  4) 오피스텔  5) 아파트  6) 빌라
④ 가격 상한 (만원)
⑤ 플랫폼
```

질문 없이 지난 조건으로 바로 시작하려면 `npm start -- --no-ask`를 쓰세요. 브라우저 자동 열기를 끄려면 `--no-open`을 붙이면 됩니다.
지도 키 같은 설정은 `.env.example`을 `.env`로 복사해서 넣습니다.

## 자연어 검색 (AI)

위쪽 검색창에 원하는 조건을 **문장으로** 입력하고 Enter를 누르면 됩니다.

```
강남역 근처 월세 60 이하 풀옵션 원룸, 반지하 제외, 관리비 10만 이하
보증금 1억5천 이하 전세 투룸 10평 이상 엘베 있는 곳
망원동 1000/50 정도 조용한 원룸
```

동작 방식은 RAG(검색 후 판단)입니다.

1. **해석:** 문장에서 확실한 조건(거래유형·방 종류·가격·관리비·면적·층·역/동·반지하 제외)을 뽑습니다. 나머지 단어(풀옵션, 신축, 조용한 등)는 선호 키워드로 둡니다
2. **검색:** 확실한 조건으로 수집된 매물을 거르고, 선호 키워드가 많이 맞는 순서로 후보를 최대 60개 고릅니다
3. **판단 (AI):** Claude가 후보 매물 정보를 읽고 요청에 맞는 매물을 골라 순위를 매기고, 고른 이유를 한 문장씩 붙입니다

`.env`에 `ANTHROPIC_API_KEY`를 넣으면 3단계까지 동작하고, 검색창 오른쪽에 **AI** 표시가 나타납니다.
키가 없으면 1~2단계 결과(키워드·가격순)만 보여 줍니다.
API 키는 https://console.anthropic.com 의 **API Keys**에서 발급합니다. 비용은 검색 1회에 대략 몇십 원 수준입니다.

- 모델: `claude-opus-5-5` (`AI_MODEL`로 변경 가능). effort `low`로 호출하고, 응답 형식을 JSON 스키마로 고정합니다
- 거절 응답에 대비해 서버 측 대체 모델(`fallbacks: "default"`)을 켜 두었습니다
- AI 호출이 실패하면 자동으로 기본 검색 결과를 보여 줍니다
- 매물 제목은 외부 사이트에서 온 데이터이므로, 그 안에 있는 지시문은 따르지 않도록 프롬프트에서 분리합니다

## 지도 설정 (카카오 / 네이버)

`.env`에서 둘 중 하나를 설정합니다. 둘 다 무료 사용량 안에서 쓸 수 있습니다.

### 카카오맵

1. https://developers.kakao.com 에 로그인한 뒤 **내 애플리케이션 → 애플리케이션 추가하기**를 누릅니다
2. **앱 키 → JavaScript 키**를 복사합니다
3. **플랫폼 → Web → 사이트 도메인**에 `http://localhost:3000`을 등록합니다. 휴대폰에서 접속할 주소가 있다면 그것도 등록합니다
4. `.env`에 다음을 넣습니다

```
MAP_PROVIDER=kakao
KAKAO_MAP_KEY=복사한_JavaScript_키
```

### 네이버 지도

1. https://console.ncloud.com 의 **Services → Application Services → Maps**에서 Application을 등록합니다. Dynamic Map을 선택하세요
2. **Web 서비스 URL**에 `http://localhost:3000`을 등록합니다
3. 발급된 **Client ID**를 `.env`에 넣습니다

```
MAP_PROVIDER=naver
NAVER_MAP_KEY_ID=발급받은_Client_ID
```

키가 틀렸거나 도메인이 등록되지 않았으면 콘솔에 경고를 남기고 OpenStreetMap 지도로 자동 대체합니다.

## 수집 설정 (`.env`)

| 변수 | 기본값 | 설명 |
|---|---|---|
| `DATA_MODE` | `live` | `live`는 실제 크롤링, `mock`은 가상 데이터 |
| `SOURCES` | 전체 | 예: `zigbang,dabang,naver,peterpan` |
| `CRAWL_INTERVAL_MIN` | `60` | 자동 재수집 간격(분). `0`이면 시작 시 1회만 수집 |
| `CRAWL_DELAY_MS` | `1500` | 같은 사이트에 보내는 요청 사이 간격 |
| `CRAWL_MAX_PAGES` | `3` | 한 지역에서 소스별로 가져올 최대 페이지 수 |

수집 지역·유형·가격은 `.env`가 아니라 `npm start` 질문이나 웹의 "수집 조건"에서 정합니다.
지도 영역 수집은 서버 부담과 차단을 막기 위해 한 변이 6km 이하인 화면에서만 동작합니다.

## 소스별 상태

| 소스 | 방식 | 상태 |
|---|---|---|
| 직방 | geohash 단위 핀 조회 후 15개씩 상세 조회 | 2026-10 기준 공개된 참고 구현으로 형식 확인 |
| 다방 | v5 bbox 목록 API, 페이지당 24개 | 원룸·투룸은 확인됨. 빌라·오피스텔 필터는 추정 |
| 네이버부동산 | `fin.land.naver.com` boundedArticles | 요청·응답 형식은 참고 구현 기준이고 실측은 못 함. **차단이 가장 엄격**해서 429를 받으면 15분 쉼 |
| 피터팬 | `api.peterpanz.com/houses/area` | **미검증(β)**. 공개 참고 자료가 없어 형태를 추정해 작성 |

> 이 저장소는 개발 환경에서 각 사이트에 접속할 수 없어서 **실제 사이트에 대고 돌려보지는 못했습니다.**
> 요청 흐름과 변환은 조사한 응답 형태로 만든 테스트로 검증했습니다.
> 사이트들은 비공식 API를 예고 없이 바꾸므로 언제든 깨질 수 있습니다.

### 수집이 안 될 때

```bash
npm run crawl -- --source naver               # 해당 소스만 실행해 결과·오류 출력
npm run crawl -- --source peterpan --dump     # 원본 응답을 data/debug/peterpan.json 에 저장
npm run crawl -- --bbox 37.49,127.02,37.51,127.05 --pages 1
```

- `HTTP 400`: 요청 형식이 바뀐 것입니다. 해당 어댑터의 요청 파라미터를 확인하세요
- `HTTP 403`/`429` 또는 `JSON 이 아닌 응답`: 차단된 것입니다. `CRAWL_DELAY_MS`를 늘리고 한참 뒤에 다시 시도하세요
- `변환 실패 N건`: 응답 필드명이 바뀐 것입니다. `--dump`로 저장한 원본을 보고 `server/sources/live/<소스>.js`의 `normalize()`를 고치세요

화면 상단 바에서 각 소스 이름에 마우스를 올리면 마지막 수집 시각과 오류 내용을 볼 수 있습니다.

## 크롤링 주의사항

- 이 도구는 **개인적인 매물 탐색용**입니다. 수집한 데이터를 공개하거나 재배포하거나 상업적으로 이용하지 마세요
- 개인용이라도 각 사이트 이용약관은 자동 수집을 금지하고 있습니다. 차단되거나 계정이 제재될 수 있다는 점을 알고 사용하세요
- 서버에 부담을 주지 않도록 사이트별 요청은 한 번에 하나씩, 1.5초 이상 간격을 두고 보냅니다. 수집 범위와 주기도 제한합니다. 이 값을 과하게 낮추지 마세요
- 로그인 우회, 캡차 우회 같은 기술적 보호조치 회피 기능은 넣지 않았습니다

## 구조

```
server/
  index.js            HTTP 서버, API, 시작 흐름(질문 → 서버 → 브라우저 → 수집)
  config.js           .env 로드, 지도 설정
  conditions.js       수집 조건 (지역 목록, 검증, 저장)
  prompt.js           터미널 질문
  search/             자연어 검색 (parse: 규칙 해석, index: 후보 검색, ai: Claude 순위·이유)
  aggregator.js       수집 결과 정규화·검증 → 중복 통합 (Union-Find)
  crawler.js          수집 실행·소스별 상태 관리
  store.js            수집된 매물 저장 (메모리 + data/*.json)
  query.js            필터·정렬·페이지
  model.js            공통 매물 스키마, 주소·층·금액 파서
  crawl/http.js       요청 간격 제한, 재시도, 쿠키를 처리하는 HTTP 클라이언트
  crawl/geo.js        bbox 분할, geohash
  sources/
    live/             실제 크롤러 (zigbang, dabang, naver, peterpan)
    mock/             가상 데이터 (개발·테스트용)
public/
  app.js              화면 로직
  maps/index.js       지도 추상화 (카카오 / 네이버 / Leaflet)
scripts/crawl.js      크롤러 점검 CLI
test/                 node:test 테스트
```

### API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/meta` | 소스별 상태, 필터 옵션, 통계, 지도 설정 |
| GET | `/api/listings` | 통합 매물 목록. 쿼리 파라미터: `q`, `dealType`, `roomType`, `source`, `depositMin`/`depositMax`, `rentMin`/`rentMax`, `areaMin`/`areaMax`, `multiSourceOnly`, `priceGapOnly`, `bounds`, `sort`, `page`, `pageSize`, `markers` |
| GET | `/api/listings/:id` | 통합 매물 상세 (플랫폼별 가격 포함) |
| POST | `/api/search` | `{ "query": "강남역 월세 60 이하 풀옵션" }`로 자연어 검색합니다. 결과는 `results: [{id, reason}]`, `mode`(ai 또는 basic) |
| GET/PUT | `/api/conditions` | 수집 조건 조회·변경. 변경하면 다른 조건의 매물을 정리하고 다시 수집합니다 |
| POST | `/api/crawl` | `{ "bounds": "남,서,북,동" }` 영역을 현재 조건으로 수집합니다 |
| GET | `/api/crawl` | 수집 진행 상태 |

### 새 소스 추가

`server/sources/live/`에 `{ key, name, color, homepage, fetchRaw(ctx), normalize(raw) }` 모듈을 만들고 `sources/index.js`에 등록합니다.
`ctx`에는 `bbox`, `maxPages`, `delayMs`, `warn()`이 들어옵니다. HTTP 요청은 `createClient()`로 보내야 요청 간격 제한이 적용됩니다.
